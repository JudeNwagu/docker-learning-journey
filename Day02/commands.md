# Docker Workflow

The commands practiced today follow the typical lifecycle below:

```text
Pull Image
     │
docker pull
     │
     ▼
List Images
     │
docker images
     │
     ▼
Create & Run Container
     │
docker run
     │
     ▼
Inspect Container
│
├── docker ps
├── docker logs
└── docker exec
     │
     ▼
Stop Container
│
docker stop
     │
     ▼
Restart (optional)
│
docker start
     │
     ▼
Delete Container
│
docker rm
     │
     ▼
Delete Image
│
docker rmi
```

# Image Management Commands

---

## docker pull

### Purpose

Downloads a Docker image from Docker Hub without starting a container.

### Syntax

```bash
docker pull <image-name>
```

### Examples

```bash
docker pull nginx

docker pull redis

docker pull postgres
```

### Why I Used It

Before Docker can create a container, it needs the image stored locally.

---

## docker images

### Purpose

Lists all Docker images currently stored on the machine.

### Syntax

```bash
docker images
```

### Typical Output

```text
REPOSITORY      TAG       IMAGE ID

nginx           latest    xxxxxx

redis           latest    xxxxxx

postgres        latest    xxxxxx
```

### Why I Used It

To verify image downloads before creating containers.

---

## docker rmi

### Purpose

Removes one or more Docker images.

### Syntax

```bash
docker rmi <image>
```

### Example

```bash
docker rmi nginx

docker rmi redis

docker rmi postgres
```

### Notes

Docker only removes images that are no longer being used by containers.

# Container Management Commands

---

## docker run

### Purpose

Creates and starts a new container from an image.

### Syntax

```bash
docker run [OPTIONS] IMAGE
```

### Examples

Nginx

```bash
docker run -d -p 8080:80 --name jcn-nginx nginx
```

Redis

```bash
docker run -d -p 6379:6379 --name jcn-redis redis
```

Postgres

```bash
docker run -d -p 5432:5432 \
--name my-postgres \
-e POSTGRES_PASSWORD=mysecretpassword \
-e POSTGRES_USER=judoski \
-e POSTGRES_DB=learning_db \
postgres
```

### Options Used

| Option | Description |
|---------|-------------|
| `-d` | Run container in detached mode |
| `-p` | Publish container port |
| `--name` | Assign container name |
| `-e` | Set environment variable |

---

## docker ps

### Purpose

Displays only running containers.

### Syntax

```bash
docker ps
```

### Why I Used It

To verify whether Nginx, Redis and PostgreSQL were currently running.

---

## docker ps -a

### Purpose

Displays every container, including stopped ones.

### Syntax

```bash
docker ps -a
```

### Why I Used It

Useful when checking failed containers or verifying successful cleanup.

---

## docker stop

### Purpose

Gracefully stops a running container.

### Syntax

```bash
docker stop <container-name>
```

### Example

```bash
docker stop jcn-nginx

docker stop my-postgres
```

### Notes

Stopping a container does **not** remove it.

---

## docker start

### Purpose

Starts an existing stopped container.

### Syntax

```bash
docker start <container-name>
```

### Example

```bash
docker start my-postgres
```

---

## docker rm

### Purpose

Deletes a stopped container permanently.

### Syntax

```bash
docker rm <container-name>
```

### Example

```bash
docker rm my-postgres
```

### Important

Docker requires containers to be stopped before they can be removed.

# Container Inspection Commands

---

## docker logs

### Purpose

Displays the log output generated by a container.

### Syntax

```bash
docker logs <container-name>
```

### Example

```bash
docker logs jcn-nginx
```

### Why I Used It

To verify:

- Nginx started correctly.
- Redis accepted connections.
- PostgreSQL initialized successfully.

---

## docker exec

### Purpose

Runs commands inside a running container.

### Syntax

```bash
docker exec -it <container> <command>
```

### Examples

Open Bash

```bash
docker exec -it jcn-nginx bash
```

Open Redis CLI

```bash
docker exec -it jcn-redis redis-cli
```

Open PostgreSQL CLI

```bash
docker exec -it my-postgres psql -U judoski -d learning_db
```

### Why I Used It

To interact directly with software running inside containers without installing those applications on my host machine.

# Interactive Application Commands

Once connected to a container, I interacted with the application itself rather than Docker.

---

## Redis CLI

Store data

```text
SET myname Judoski
```

Retrieve data

```text
GET myname
```

List keys

```text
KEYS *
```

Delete key

```text
DEL myname
```

Exit

```text
exit
```

---

## PostgreSQL (psql)

Create table

```sql
CREATE TABLE learners (
    id SERIAL PRIMARY KEY,
    name TEXT
);
```

Insert data

```sql
INSERT INTO learners (name)
VALUES ('Judoski');
```

Retrieve data

```sql
SELECT * FROM learners;
```

List databases

```sql
\l
```

Quit

```sql
\q
```

# Common Mistakes Encountered

| Mistake | Correct Command |
|----------|----------------|
| `docker log` | `docker logs` |
| `docker -d` | `docker run -d` |
| Missing image name | Add image name after options |
| Duplicate container name | Use a unique name |
| Running Docker inside `redis-cli` | Exit Redis CLI first |
| Removing running container | Stop container before removing |

# Key Learning

Day 2 reinforced that Docker commands are not isolated tools—they form a complete workflow for managing containerized applications.

The same lifecycle applied consistently across Nginx, Redis, and PostgreSQL:

1. Pull an image.
2. Create a container.
3. Interact with the application.
4. Inspect logs.
5. Stop the container.
6. Remove the container.
7. Remove the image (optional).

Understanding this workflow is more valuable than memorizing individual commands because it provides a repeatable process for working with any Docker image.
